# ASTRA — LLM Integration Guide

How the `LLM` branch's `astra_llm_agent` package connects to the rebuilt
`astra_robot` stack. Two files change; the agent's Python code does not.

---

## Assessment of the LLM branch

It's solid work and I'm keeping it as-is. Notable good decisions:

- `rooms.py` has **no ROS imports**, so the resolver is unit-testable with
  plain pytest. That's a deliberate, correct separation.
- Alias collisions **raise at start-up** (`_build_alias_index`) rather than
  silently mis-routing mid-demo.
- Resolution is layered: exact key → alias → alias-inside-phrase → fuzzy
  (`difflib`, cutoff 0.75), and returns `None` instead of guessing — which is
  exactly the "ask for clarification rather than guess" behaviour the project
  workflow doc requires.
- The LLM round-trip runs on a **worker thread** with a `ReentrantCallbackGroup`,
  so a slow Mistral call doesn't block Nav2 result/feedback callbacks. This is
  the right concurrency model and it's genuinely easy to get wrong.
- `use_sim_time` is already plumbed through the launch files.

No changes needed to `llm_nav_agent.py`, `rooms.py`, or `prompt_cli.py`.

---

## What has to change, and why

### 1. `config/rooms.yaml` — REPLACE (mandatory)

The old coordinates were tuned against the **previous world**, whose 18-metre
corridor walls ran through every room and sealed every doorway. That world no
longer exists. The new `rooms.yaml` takes its coordinates from
`astra_robot/config/locations.yaml`, which is generated by
`astra_robot/tools/generate_world.py` — the script that emits the Gazebo world
and the occupancy map from one geometry definition and then proves by BFS, at
full 0.35 m costmap inflation, that every pose is collision-free and mutually
reachable.

Descriptions and aliases are carried over unchanged, **plus** missing singular
forms. The old alias list had `"engines"` and `"engine room"` but not
`"engine"`, so the workflow doc's own example — *"go fix the engine"* — resolved
to `None` and the robot would have refused it. Also added `"sleep"`, `"rest"`,
`"crates"`, `"eva"`, `"reactor"`, `"medic"`, and others.

Verified against the branch's own `RoomTable`: 6 rooms load, zero alias
collisions, and 14/14 phrasing tests pass including correct `None` for unknown
rooms like "kitchen".

### 2. `launch/astra_llm_demo.launch.py` — REPLACE with `astra_full_demo.launch.py`

The old one includes `rosbot_description/gazebo.launch.py` and
`rosbot_nav2_bringup/nav2.launch.py`. Both packages are gone. The replacement
includes `astra_robot`'s launch files instead, and additionally sets:

- `use_sim_time: True` (the agent stamps goals with the clock; Nav2/Gazebo run
  on sim time — wall-clock stamps make the TF lookup fail and Nav2 rejects the
  goal)
- `robot_base_frame: 'base_footprint'` (the agent defaulted to `base_link`;
  `astra_robot`'s URDF and `nav2_params.yaml` both use `base_footprint`. Both
  frames exist so `get_robot_pose` would work either way, but matching the rest
  of the stack avoids a confusing offset in reported positions.)

Staged startup: Gazebo at t=0, Nav2 at t=12s, agent at t=25s. The agent needs
the `navigate_to_pose` action server to exist before it starts, or its first
tool call reports "server unavailable".

## Install

```bash
# 1. Both packages into one workspace
mkdir -p ~/astra_ws/src
cp -r astra_robot      ~/astra_ws/src/
cp -r astra_llm_agent  ~/astra_ws/src/     # from the LLM branch

# 2. Apply the two integration files
cp integration/astra_llm_agent/config/rooms.yaml \
   ~/astra_ws/src/astra_llm_agent/config/rooms.yaml
cp integration/astra_llm_agent/launch/astra_full_demo.launch.py \
   ~/astra_ws/src/astra_llm_agent/launch/
rm -f ~/astra_ws/src/astra_llm_agent/launch/astra_llm_demo.launch.py

# 3. Python deps for the agent (pip, not rosdep)
pip install "langchain<1.0.0" "langchain-mistralai<1.0.0" python-dotenv

# 4. API key
cp ~/astra_ws/src/astra_llm_agent/config/openai.env.example \
   ~/astra_ws/src/astra_llm_agent/config/openai.env
# edit it and put your MISTRAL_API_KEY in

# 5. Build
cd ~/astra_ws
colcon build
source install/setup.bash
```

## Run

**Everything at once:**
```bash
ros2 launch astra_llm_agent astra_full_demo.launch.py
```

**Then drive it with natural language:**
```bash
ros2 run astra_llm_agent prompt_cli
> go check the cargo bay
> now go fix the engine
> where are you?
> take me to the kitchen        # agent should ask for clarification
```

**Or manually, three terminals** (better for debugging — you see each layer):
```bash
ros2 launch astra_robot spacecraft.launch.py       # T1
ros2 launch astra_robot nav2.launch.py             # T2
ros2 launch astra_llm_agent llm_agent.launch.py    # T3
```

## Two paths to Nav2 — keep them straight

Both packages can send `NavigateToPose` goals:

| Path | Use for |
|---|---|
| `astra_llm_agent` (`llm_nav_agent`) | **The real deliverable.** Natural language → LangChain/Mistral → Nav2. This is what you demo. |
| `astra_robot` (`astra_navigator`, `demo_tour`) | Testing and the demo video. `demo_tour` visits all six rooms with no LLM and no API key — proves navigation independently of the LLM, which is invaluable when something breaks and you need to know which half is at fault. |

Don't run both sending goals at once — the second goal preempts the first.
`llm_nav_agent` already logs a warning when it replaces a goal in progress.

## Report notes

For the System Architecture section, the LLM layer sits **on top of** Nav2 and
does not replace it:

```
natural language ──▶ LangChain agent (Mistral)
                          │  tools: navigate_to_room, navigate_to_coordinates,
                          │         list_rooms, get_robot_pose
                          ▼
                   rooms.yaml  (semantic → coordinate mapping)
                          ▼
                   NavigateToPose action  (frame: map)
                          ▼
                        Nav2  ── planning, control, obstacle avoidance
```

The brief's required components map cleanly:
*LangChain tools* → `_build_tools()`; *semantic-to-coordinate mapping* →
`rooms.yaml` + `RoomTable.resolve()`; *ROS 2 interface node* →
`llm_nav_agent.py`; *optional reasoning/validation* → the `None`-on-no-match
behaviour that makes the agent ask rather than guess.
